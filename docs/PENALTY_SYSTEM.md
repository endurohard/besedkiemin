# Система штрафов - Besedki EMIN

## Обзор

Система штрафов позволяет назначать денежные взыскания сотрудникам за брак, нарушения или другие причины. Штрафы автоматически учитываются в расчёте заработной платы и вычитаются из итоговой суммы выплаты.

---

## Предопределённые суммы штрафов

Суммы штрафов фиксированы и выбираются из предопределённого списка. Произвольный ввод суммы невозможен — валидация на бэкенде отклонит любое значение вне списка.

| Группа | Суммы (руб.) |
|--------|-------------|
| Малые штрафы | 200, 400, 600, 800, 1 000 |
| Крупные штрафы | 1 500, 2 000, 2 500, 3 000, 3 500, 4 000, 4 500, 5 000 |

Константа определена в `backend/src/common/constants.ts`:
```typescript
export const PENALTY_AMOUNTS = [200, 400, 600, 800, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500, 5000];
```

---

## Роли и права доступа

### Складист (WAREHOUSE)
- Просмотр всех штрафов
- Создание штрафов (выбор сотрудника, суммы из списка, причины)
- Назначение штрафа при браковке продукта на контроле качества
- **Не может** редактировать или отменять штрафы

### Владелец (OWNER)
- Полный доступ: просмотр, создание, редактирование, отмена штрафов
- Управление расчётными периодами с учётом штрафов

### SUPER_ADMIN
- Полный доступ (аналогично OWNER)

### Производственные работники (PAINTER, SEWER, ASSEMBLER и др.)
- Видят свои штрафы в разделе «Мои заработки»
- Получают Telegram-уведомления о назначенных штрафах
- **Не могут** создавать, редактировать или отменять штрафы

## Модель данных

Таблица `penalties` в PostgreSQL:

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Уникальный идентификатор |
| user_id | UUID | Сотрудник, которому назначен штраф |
| amount | Float | Сумма штрафа (из предопределённого списка) |
| reason | String | Причина штрафа (обязательное поле) |
| product_id | UUID? | Связь с продуктом (если штраф за брак) |
| created_by_id | UUID | Кто назначил штраф |
| date | DateTime | Дата штрафа (по умолчанию — текущая) |
| notes | String? | Дополнительные заметки |
| is_cancelled | Boolean | Отменён ли штраф (default: false) |
| cancelled_at | DateTime? | Дата отмены |
| cancelled_by_id | UUID? | Кто отменил |
| payroll_period_id | UUID? | Связь с расчётным периодом |
| created_at | DateTime | Дата создания записи |
| updated_at | DateTime | Дата последнего обновления |

Индекс: `(user_id, date)` для быстрой выборки штрафов по сотруднику и дате.

## API-эндпоинты

Все эндпоинты находятся под `/payroll/` и требуют JWT-авторизацию.

### GET /payroll/penalties/amounts
Возвращает список допустимых сумм штрафов.

**Доступ:** любой авторизованный пользователь

**Ответ:**
```json
{
  "amounts": [200, 400, 600, 800, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500, 5000]
}
```

---

### GET /payroll/penalties
Получить список штрафов с фильтрацией.

**Доступ:** SUPER_ADMIN, OWNER, WAREHOUSE

**Query-параметры:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| userId | string? | Фильтр по сотруднику |
| startDate | string? | Начало периода (ISO 8601) |
| endDate | string? | Конец периода (ISO 8601) |
| includeCancelled | string? | `"true"` — включить отменённые штрафы |

**Ответ:** массив объектов Penalty с вложенными `user`, `product`, `createdBy`.

---

### POST /payroll/penalties
Создать новый штраф.

**Доступ:** SUPER_ADMIN, OWNER, WAREHOUSE

**Тело запроса (JSON):**
```json
{
  "userId": "uuid-сотрудника",
  "amount": 1000,
  "reason": "Брак при покраске",
  "productId": "uuid-продукта",
  "date": "2026-03-28",
  "notes": "Повторный брак"
}
```

**Поля:**
- `userId` — обязательное, UUID сотрудника
- `amount` — обязательное, число из списка PENALTY_AMOUNTS
- `reason` — обязательное, строка
- `productId` — опциональное, UUID продукта
- `date` — опциональное, ISO дата (по умолчанию сегодня)
- `notes` — опциональное, строка

**Валидация:**
- При невалидной сумме: `400 Bad Request` с сообщением «Сумма штрафа должна быть из предопределённого списка»

**Побочные эффекты:**
- Отправляется Telegram-уведомление сотруднику (если привязан Telegram)

---

### PUT /payroll/penalties/:id
Обновить существующий штраф.

**Доступ:** SUPER_ADMIN, OWNER (складист НЕ может)

**Тело запроса (JSON):**
```json
{
  "amount": 2000,
  "reason": "Новая причина",
  "notes": "Уточнение"
}
```

Все поля опциональные. Сумма должна быть из PENALTY_AMOUNTS.

---

### POST /payroll/penalties/:id/cancel
Отменить штраф.

**Доступ:** SUPER_ADMIN, OWNER (складист НЕ может)

**Тело запроса (JSON):**
```json
{
  "notes": "Причина отмены"
}
```

**Ограничения:**
- Нельзя отменить штраф, включённый в расчётный период со статусом `PAID`
- Нельзя отменить уже отменённый штраф

## Интеграция с браковкой (контроль качества)

### Через форму браковки в карточке задачи

Когда складист бракует продукт на этапе контроля качества, он может **опционально** назначить штраф:

1. Складист нажимает «Брак» на карточке задачи
2. Заполняет причину, выбирает этап возврата
3. Ставит галочку «Назначить штраф»
4. Выбирает сумму из предопределённых кнопок
5. Нажимает «Забраковать»

**Что происходит:**
- Продукт возвращается на указанный этап производства
- Создаётся задача на доработку для исполнителя
- Если выбран штраф — автоматически создаётся запись Penalty:
  - `userId` = последний исполнитель на этапе (из ProductHistory)
  - `amount` = выбранная сумма
  - `reason` = причина браковки
  - `productId` = ID бракованного продукта
  - `createdById` = ID складиста
- Отправляется Telegram-уведомление о штрафе

### API: POST /tasks/:id/reject

Параметр `penaltyAmount` (опциональный):
```json
{
  "notes": "Царапина на покраске",
  "quantity": 1,
  "returnToStage": "PAINTING",
  "requestPhoto": true,
  "penaltyAmount": 1000
}
```

## Telegram-уведомления

При назначении штрафа сотрудник получает уведомление в Telegram:

```
⚠️ Вам назначен штраф!

💰 Сумма: 1 000 ₽
📝 Причина: Царапина на покраске
👤 Назначил: Иванов Петр
📅 Дата: 28.03.2026
```

**Требования:**
- У сотрудника должен быть привязан Telegram ID (авторизация через Telegram-бот)
- Если Telegram ID отсутствует, уведомление пропускается без ошибки

Метод: `TelegramService.sendPenaltyNotification()` в `backend/src/telegram/telegram.service.ts`

## Интерфейс пользователя

### Страница «Штрафы» (для WAREHOUSE)

- Доступ через боковое меню: ссылка «Штрафы» (иконка кошелька)
- Маршрут: `/app/payroll`
- Складист видит **только вкладку «Штрафы»** (без «Сводка», «Расчёты», «Расценки»)

**Функционал:**
- Таблица штрафов с колонками: Дата, Сотрудник, Причина, Сумма, Статус, Действия
- Кнопка «+ Добавить штраф» — открывает модальное окно

### Страница «Зарплата» (для OWNER)

- Все вкладки доступны: Сводка, Расчёты, Журнал работ, Штрафы, Расценки
- Вкладка «Штрафы» — полное управление (создание, отмена)
- Штрафы учтены в сводке: `penaltyAmount` вычитается из `totalAmount`

### Модальное окно создания штрафа

1. **Выбор сотрудника** — выпадающий список всех пользователей
2. **Выбор суммы** — сетка кнопок:
   - Ряд 1 (5 кнопок): `200 ₽` `400 ₽` `600 ₽` `800 ₽` `1000 ₽`
   - Ряд 2 (8 кнопок): `1500 ₽` `2000 ₽` `2500 ₽` `3000 ₽` `3500 ₽` `4000 ₽` `4500 ₽` `5000 ₽`
   - Выбранная кнопка подсвечивается красным (bg-red-600)
3. **Причина** — текстовое поле (обязательное)
4. **Заметки** — текстовое поле (опциональное)

### Форма браковки (карточка задачи)

В форме отклонения продукта добавлен блок:
- Чекбокс «Назначить штраф»
- При активации — сетка кнопок с суммами (аналогично модалке)
- Отображение выбранной суммы: «Штраф: 1000 ₽»

### Страница «Мои заработки» (для работников)

- Работник видит свои штрафы в разделе заработков
- Штрафы отображаются в общей сводке и вычитаются из итога

## Связь с расчётом зарплаты

Штрафы интегрированы в систему расчёта заработной платы:

```
Итого к выплате = Работа (сдельная) + Комиссия (менеджерская) - Штрафы
```

- При расчёте PayrollPeriod все штрафы за период суммируются в `penaltyAmount`
- Штраф привязывается к расчётному периоду через `payrollPeriodId`
- Отменённые штрафы (`isCancelled = true`) не учитываются
- Итоговая сумма не может быть отрицательной (минимум 0 руб.)

## Сценарии использования

### Сценарий 1: Складист назначает штраф вручную
1. Складист заходит в систему, боковое меню, «Штрафы»
2. Нажимает «+ Добавить штраф»
3. Выбирает сотрудника из списка
4. Нажимает кнопку с суммой (например, 1000 руб.)
5. Вводит причину: «Опоздание на смену»
6. Нажимает «Создать штраф»
7. Сотрудник получает Telegram-уведомление

### Сценарий 2: Складист штрафует при браковке
1. Складист видит задачу на контроле качества
2. Нажимает «Брак»
3. Вводит причину: «Царапина на покраске»
4. Выбирает этап возврата: «Покраска»
5. Ставит галочку «Назначить штраф»
6. Выбирает сумму 600 руб.
7. Нажимает «Забраковать»
8. Продукт возвращается на покраску, маляр получает задачу на доработку
9. Маляр получает Telegram: уведомление о браке + уведомление о штрафе

### Сценарий 3: Владелец отменяет штраф
1. Владелец заходит, «Зарплата», вкладка «Штрафы»
2. Находит штраф в таблице
3. Нажимает «Отменить»
4. Подтверждает отмену
5. Штраф помечается как отменённый (отображается серым)
6. Сумма штрафа больше не вычитается из зарплаты

### Сценарий 4: Работник проверяет свои штрафы
1. Работник заходит в систему, «Мои заработки»
2. Видит список своих заработков и штрафов
3. Штрафы отображаются в красном цвете с причиной
4. Итоговая сумма к выплате учитывает вычет штрафов

## Безопасность и валидация

1. **Валидация суммы** — бэкенд отклоняет любую сумму не из PENALTY_AMOUNTS (HTTP 400)
2. **Контроль доступа** — RolesGuard проверяет роль пользователя:
   - SUPER_ADMIN: полный доступ
   - OWNER: полный доступ (кроме эндпоинтов ONLY SUPER_ADMIN)
   - WAREHOUSE: только просмотр и создание
   - Остальные роли: доступ запрещён (HTTP 403)
3. **Защита от двойной отмены** — нельзя отменить уже отменённый штраф
4. **Защита выплаченных периодов** — нельзя отменить штраф в периоде со статусом PAID
5. **JWT-авторизация** — все эндпоинты защищены JwtAuthGuard

## Изменение списка сумм

Для добавления или изменения допустимых сумм штрафов:

1. Отредактировать файл `backend/src/common/constants.ts`:
   ```typescript
   export const PENALTY_AMOUNTS = [200, 400, 600, 800, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500, 5000];
   ```
2. Обновить фронтенд-кнопки в:
   - `frontend/src/pages/PayrollPage.tsx` — модалка создания штрафа
   - `frontend/src/components/task-card/TaskCardWarehouseActions.tsx` — форма браковки
3. Перезапустить backend (или дождаться hot-reload в dev-режиме)
4. Пересобрать frontend: `docker compose build --no-cache frontend && docker compose up -d frontend`

**Примечание:** суммы на фронтенде дублируются для визуального представления. Бэкенд является единственным источником истины — невалидные суммы будут отклонены при сохранении.
